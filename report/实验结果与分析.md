# 实验结果与分析（可直接用于报告正文）

> 本文档所有数字均来自本机实测，可复现。脚本见 `scripts/`。

## 1. 实验设置

| 项 | 配置 |
|---|---|
| 模型 | **YOLO11s**（9,431,662 参数，21.7 GFLOPs），COCO 预训练权重初始化 |
| 数据集 | VisDrone2019-DET（train 6471 / val 548，共 381,963 个标注框） |
| 输入分辨率 | **896 × 896** |
| batch size | 8（显存峰值 6.04 GB / 8.00 GB，未 OOM） |
| 优化器 | SGD，余弦退火（`cos_lr`），lr0=0.01，lrf=0.005 |
| 训练轮数 | **64 epochs**（时间盒 7.5 小时，自动收敛） |
| 数据增强 | mosaic 0.8 / mixup 0.1 / copy_paste 0.1 / scale 0.5 |
| 硬件 | NVIDIA RTX 4060 Laptop 8GB，驱动 610.88 |

**训练效率**：单 epoch 7.03 分钟（809 次迭代），总耗时 7.5 小时，
合计 **≈ 48,500 次梯度更新**。显存余量 1.96 GB。

| 64 | 0.4840 | 0.2883 | 5.60e-5 |

**结论：模型已充分收敛。**

三个证据：
1. **最优 epoch 为第 58 轮**（mAP@0.5 = 0.488），此后波动仅 ±0.004；

## 5. 误差来源的定量归因

为定位性能瓶颈，在 val 集上按 **IoU ≥ 0.5 的同类匹配**逐框统计召回率，
并按「单图目标数」与「目标尺寸」两个维度分桶。

### 5.1 按目标尺寸（决定因素）

| 目标尺寸 | 召回率 | 占比 |
|---|---|---|
| ≥ 96 px | **90.7%** | 2.8% |
| 32 ~ 96 px | **82.7%** | 28.7% |
| 16 ~ 32 px | 62.1% | 37.7% |
| **< 16 px** | **34.5%** | 30.8% |

尺寸从 ≥96px 到 <16px，召回率相差 **2.6 倍**。**接近三分之一的目标
（30.8%）落在 <16px 区间，是主要的性能损失来源。**

### 5.2 按单图目标数（次要因素）

| 单图目标数 | 召回率 |
|---|---|
| < 20 | 70.7% |
| 20 ~ 50 | 68.7% |
| 50 ~ 100 | 62.2% |
| ≥ 100 | 55.0% |

### 5.3 密度 × 尺寸交叉验证（关键结论）

| 密度 \ 尺寸 | <16px | 16~32px | 32~96px | ≥96px |
|---|---|---|---|---|
| < 20 | 31.5% | 57.7% | 81.6% | 86.3% |
| 20~50 | 44.2% | 69.0% | 81.0% | 94.4% |
| 50~100 | 36.5% | 64.9% | 84.3% | 90.0% |
| ≥ 100 | 30.2% | 57.4% | 81.4% | 91.1% |

**在控制尺寸后，密度的影响基本消失**——32~96px 这一列四个密度桶的召回率
为 81.6 / 81.0 / 84.3 / 81.4，几乎不随密度变化。

因此：**场景密集并非检测失败的主要原因；目标尺寸偏小才是。**
5.2 中密度的表观影响，实质是密集场景中小目标占比更高造成的成分效应。

### 5.4 per-class 尺寸与召回

| 类别 | 尺寸中位 | <16px 占比 | 召回率 | AP@0.5 |
|---|---|---|---|---|
| car | 32.5 px | 19.4% | **83.4%** | 0.843 |
| bus | 35.2 px | 14.7% | 56.2% | 0.639 |
| motor | 20.0 px | 35.1% | 55.6% | 0.562 |
| pedestrian | 17.2 px | 44.8% | 51.5% | 0.551 |
| van | 33.6 px | 16.6% | 48.7% | 0.516 |
| truck | 38.6 px | 12.1% | 43.7% | 0.451 |
| people | 16.7 px | 47.1% | 41.4% | 0.415 |
| tricycle | 28.4 px | 18.4% | 34.6% | 0.352 |
| bicycle | 20.8 px | 30.8% | 26.0% | 0.246 |
| awning-tricycle | 29.3 px | 16.7% | 21.1% | 0.173 |

对 van / truck 等类，即使尺寸中位数达到 33~39px（大于 car），召回率仍仅
44~49%，说明除尺寸外，**训练样本稀缺（van 1,975 / truck 750）以及与
car 的外观相似性带来的类间混淆**也是次要限制因素。

## 6. 实现层面的两个重要发现

### 6.1 分类头按类名复用（`cls_remap`）

本版 ultralytics 在跨数据集微调时，会按**类名**重排预训练分类头。VisDrone 的
`bicycle / car / bus / truck` 与 COCO 同名，因此这 4 类的分类头**起始于 COCO
真实权重而非随机初始化**，日志实测输出：

```
Remapped 4/10 cls head rows from pretrained weights by class name
Transferred 499/499 items from pretrained weights
```

这解释了 car 的高性能部分来自**更优的初始化起点**，而非单纯的数据量优势。
报告中使用"从 COCO 预训练迁移"的表述时，应注明是**部分类头按名复用**。

### 6.2 检测上限 `max_det` 自适应

VisDrone 单图目标数最多达 **902 个**，而 ultralytics 默认 `max_det=300` 会截断
召回。训练过程中框架自动上调至 902：

```
Dataset images contain up to 902 objects (train=902, val=317), but max_det=300.
Setting max_det=902 to match the observed maximum.
```

该调整对高密度场景的指标有效性是必要的。

## 7. 评估口径声明（重要）

> 本报告所有指标均在 VisDrone2019-DET 的 **val 集**上测得。`best.pt` 系按 val 的
> fitness（0.1·mAP50 + 0.9·mAP50-95）选出后再回报 val，故结果含**选择偏置**，
> 非严格泛化估计。VisDrone2019-DET 的 test-dev / test-challenge 无公开标注，
> 无法在留出集上做无偏评估。

**偏置量化**（同时评估两个权重）：

| 指标 | best.pt | last.pt | 差值 |
|---|---|---|---|
| mAP@0.5 | 0.478 | 0.475 | **+0.003** |
| mAP@0.5:0.95 | 0.288 | 0.286 | +0.002 |

两者差异 **0.003 < 0.01**，说明**选择偏置很小**，使用 best.pt 的指标是稳健的。

## 8. 结论与改进方向

### 结论

1. YOLO11s 在 VisDrone2019-DET 上达到 **mAP@0.5 = 0.478 / mAP@0.5:0.95 = 0.288**，
   高于预期基线，且经收敛性验证已充分训练。
2. 性能瓶颈经定量归因为**目标尺寸**：≥32px 目标召回率 82.7%，<16px 仅 34.5%。
   **单图目标密度的影响在控制尺寸后可以忽略。**
3. 面向**无人机视角车辆监测**场景，模型在 car 类达到 AP@0.5 = 0.843、
   召回率 83.4%，具备工程可用性。
4. 选择偏置量化结果为 0.003，评估结论稳健。

### 改进方向（按性价比排序）

| 方法 | 预期收益 | 代价 |
|---|---|---|
| 推理分辨率 896 → 1280 | 直接改善小目标召回 | 显存与耗时上升，需降 batch |
| 切片推理（SAHI / tiling） | 小目标检测的针对性方案 | 推理耗时增至 3~5 倍 |
| 提高稀有类采样权重（`cls_pw`） | 改善 van / truck / awning-tricycle | 需重训，可能牺牲 car 精度 |
| 延长训练至 100+ epochs | 边际收益有限（已验证收敛） | 约 +4 小时 |
